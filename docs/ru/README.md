# Руководство пользователя CodexManager

[中文](../../README.md) · [English](../en/README.md) · [한국어](../ko/README.md)

CodexManager — локальный менеджер аккаунтов и OpenAI-совместимый gateway. Он управляет авторизованными аккаунтами, platform API key, каталогом моделей и сторонними upstream Aggregate API, а затем предоставляет локальный API для клиентов.

## 1. Установка и запуск (Windows)

Загрузите один файл из [Releases](https://github.com/qxcnm/Codex-Manager/releases):

- `CodexManager_<version>_x64-setup.exe` — версия с установщиком.
- `CodexManager-portable.exe` — portable-версия; поместите файл в любую доступную для записи папку и запустите.

После первого запуска проверьте состояние локального service. Адрес по умолчанию — `localhost:48760`. Если порт не менялся в Settings, используйте в клиенте `http://localhost:48760/v1`.

## 2. Авторизация аккаунта

1. Запустите service с главной страницы: остановленный gateway не обрабатывает запросы.
2. Откройте **Account Management**, добавьте аккаунт и завершите авторизацию в браузере.
3. Если callback не распознан автоматически, вставьте callback URL в приложение для ручного разбора.
4. Обновите usage и статус; убедитесь, что аккаунт доступен, и только затем создавайте platform key.

Аккаунты, authorization callback и экспортированные данные являются конфиденциальными. Не передавайте их и не добавляйте в репозиторий.

## 3. Platform API key и подключение клиента

1. Откройте **Platform Keys**, создайте key и при необходимости выберите разрешённые модели и уровни reasoning.
2. Настройте клиент:

   ```text
   Base URL: http://localhost:48760/v1
   API Key: <ваш-platform-key>
   Authorization: Bearer <ваш-platform-key>
   ```

3. Основные совместимые endpoints:

   - `POST /v1/responses`
   - `POST /v1/chat/completions`

Key в примере — только заполнитель. Не публикуйте реальные ключи в скриншотах, чатах, шаблонах или открытых репозиториях.

## 4. Модели GPT-5.6

На странице **Models** и в настройках platform key показан каталог, разрешённый вашим аккаунтом.

| Отображаемое имя | Model slug |
| --- | --- |
| GPT-5.6 (алиас GPT-5.6 Sol) | `gpt-5.6` |
| GPT-5.6 Sol | `gpt-5.6-sol` |
| GPT-5.6 Terra | `gpt-5.6-terra` |
| GPT-5.6 Luna | `gpt-5.6-luna` |

Уровни reasoning: `none`, `low`, `medium`, `high`, `xhigh`, `max`. Наличие модели в каталоге не гарантирует API-доступ: видимость, доступность API и уровни reasoning зависят от аккаунта и результата запроса.

## 5. Настройка upstream Aggregate API

Aggregate API подключает совместимый сторонний upstream.

1. Откройте **Aggregate API**, добавьте upstream и заполните имя, адрес и upstream key.
2. Используйте базовый URL, например `https://api.example.com`; не добавляйте `/v1`. Gateway сам добавляет путь клиента, поэтому `/v1` в адресе может дать `/v1/v1/...`.
3. Проверьте соединение в приложении, затем задайте model mappings и priority.
4. Привяжите нужные модели к upstream; при нескольких upstream выбор определяется priority.

Upstream key — секрет. Храните его только в локальных настройках приложения.

## 6. Proxy и сеть

В **Settings** настраиваются upstream proxy, тайм-ауты и SSE keepalive. Для доменов, которым требуется прямое подключение, используйте **Proxy Bypass Domains**; это отдельная настройка от upstream proxy.

По умолчанию gateway рассчитан на локальное использование. Перед публикацией в LAN или Интернете включите platform keys и ограничьте доступ firewall, reverse proxy или другими сетевыми средствами. Никогда не открывайте публичный gateway без аутентификации.

## 7. Устранение неполадок

**Клиент не подключается:** убедитесь, что service запущен, Base URL — `http://localhost:48760/v1`, а порт не заблокирован.

**401 или ошибка прав:** используйте platform key, а не upstream key; проверьте, что key включён и разрешает модель.

**Модель отсутствует или запрос не проходит:** обновите статус аккаунта и каталог моделей; доступ зависит от аккаунта.

**Aggregate API формирует неверный URL:** удалите дублирующий `/v1` из базового URL и повторите тест.

## 8. Сборка из исходников (Windows)

Установите Rust, Node.js, pnpm и PowerShell 7 (`pwsh`). В корне репозитория выполните:

```powershell
pwsh -NoLogo -NoProfile -File scripts/rebuild.ps1 -Bundle nsis -CleanDist -Portable
```

Установщик будет в Tauri bundle output, а portable-файл — `portable/CodexManager-portable.exe`.

## Безопасность и отказ от ответственности

Проект предназначен для обучения и разработки. Соблюдайте условия upstream-платформ и не используйте его для обхода service или rate limits. Вы несёте ответственность за аккаунты, API keys, proxy и сетевую публикацию.
